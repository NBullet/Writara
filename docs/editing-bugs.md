# 编辑体验 bug 清单

> 用途：把「用起来不对劲」的问题收成一份可跟踪的清单，并按「是否需要换引擎验证」分类，
> 避免在浏览器里修一遍、装进 Electron 后再修一遍。
> 新增条目的规则见文末。

## 分类

| 类 | 含义 | 在哪修 |
| --- | --- | --- |
| **A** | 纯逻辑 / 纯布局计算，与运行环境无关 | 浏览器（`npm run dev`），用 `analyze.test.ts` / `render.test.ts` 钉住 |
| **B** | 依赖渲染引擎：命中测试、IME、滚动高度、字体断行、焦点 | **只在 Electron 里修**（`npm run dev:electron`），修完补用例 |
| **C** | 其实是浏览器能力缺失，迁移后自然消失 | 不修，等平台层/M1 落地 |
| **D** | 功能缺失（不是 bug） | 进路线图，不混进这张表 |

判断 B 类的经验：只要现象和「点在哪 → 光标落在哪」「输入法」「滚动位置」有关，就按 B 处理。

## 修复纪律

1. **先写现象，不写猜测**：现象 + 复现步骤 + 是否与输入法/滚动/点击坐标有关。
2. **A 类必须有回归用例**，否则不算修完；用例放在对应的 `*.test.ts`。
3. **B 类只在 Electron 里修**。修之前先 `npm run dev:electron` 确认现象能复现；
   浏览器里能复现、Electron 里不能的现象，多半是 C 类或已经消失。
4. **不要为了绕现象加 hack**。加之前先确认目标引擎（Electron 45 / Chromium）还需要它；
   `AGENTS.md` 里的约束是历史结论，换引擎后要重新验证。
5. 修完把状态改成 ✅ 并写一行「怎么修的」，别只写「已修复」。

## 已知的性能预算

| 操作 | 目标 | 现状（20k 行 / 440KB） |
| --- | --- | --- |
| 普通文档敲字（无 `<svg`） | < 1ms | 0.034ms |
| 含 `<svg` 的文档敲字 | < 5ms | 4.15ms（每次重扫） |
| 只移动光标 | < 0.5ms | 仅重算若干块的显隐 |
| 打印预渲染（停笔 1.5s 后） | 不阻塞输入 | 组合期直接跳过 |

含 `<svg` 的文档仍然每次重扫。要再降，需要把「变更范围 → 块区间」做成增量映射，
风险高于收益，等有真实卡顿反馈再做。
