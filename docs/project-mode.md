# 项目模式（设计定稿）

> 2026-10-26。身份 / 资源树 / 顺序 / 双导出 / 多文件 AI 已落地；剩余切片见文末。
> 一句话：**项目 = 工作区文件夹 + 指令文件（`WRITARA.md` / `AGENTS.md`）**，清单可缺省。

## 1. 定义

- **工作区**：一个根目录。它是扫描、权限、文件监听、最近列表、持久化的唯一边界。
- **项目**：同一个根目录的语义层。根目录有 `WRITARA.md` 或 `AGENTS.md`（项目指令）即项目；
  `.writara/project.json` 是可以缺省的清单，只补「顺序 / 资料登记 / 导出默认值」。
- 没有指令文件、也没有清单的文件夹仍是普通工作区，不强制项目化。
- 项目不是「工作区里的项目」，也不是「包含多个工作区的项目」。多根见 §11。
- 正文永远是普通 `.md`，脱离 Writara 也能读写；清单只补语义，不改文件格式。

判断依据：**指令文件存在，或清单存在**。清单存在但没有指令文件时仍按项目打开（兼容旧清单），
只是 AI 上下文没有项目规范可用。

## 2. 目录布局

```
长夜/
├─ WRITARA.md            项目写作规范（已有能力，位置不变）
├─ 00-前言.md
├─ 卷一/
│  ├─ 01-起.md
│  └─ 02-承.md
├─ 资料/                  资料区（约定目录，默认不进项目导出）
│  ├─ 人物.md
│  └─ 时间线.md
└─ .writara/             应用私有（不进文件树）
   ├─ project.json       身份 / 次序 / 资料登记 / 导出默认值
   ├─ templates/
   └─ proposals/
```

- `资料/` 是约定，不是硬编码：清单里的 `resources` 可以指向任意正文目录。
- `.writara/` 继续由 `workspace/config.ts` 管前缀，新增能力只加在那里。
- 资料文件仍然出现在文件树、搜索、命令面板里；它们只是不进出稿。

## 3. 清单

```json
{
  "version": 1,
  "title": "长夜",
  "kind": "book",
  "description": "一部关于……的长篇。",
  "instructions": "WRITARA.md",
  "order": "custom",
  "spine": ["00-前言.md", "卷一/01-起.md", "卷一/02-承.md"],
  "resources": [
    { "path": "资料/人物.md", "role": "characters" },
    { "path": "资料/时间线.md", "role": "timeline" }
  ],
  "exclude": ["资料/"],
  "export": { "toc": true, "chapterBreak": true }
}
```

| 字段 | 规则 |
| --- | --- |
| `version` | 固定 `1`。大于 1 时按隐式项目打开并提示「由更新版本创建」，不猜字段 |
| `title` | 显示名，缺省为文件夹名 |
| `kind` | `book \| docs \| notes \| general`，**只在新建时决定默认值**，运行时不再分支 |
| `description` | 一句话，进 AI 上下文；不写就当没有 |
| `instructions` | 规范文件路径；缺省时按 `WRITARA.md` → `AGENTS.md` → 离文档最近的祖先规则查找 |
| `order` | `natural \| custom`，默认 `natural`；`custom` 时按 `spine` 排序。旧清单有 `spine` 但无此字段时视为 `custom` |
| `spine` | 有序正文列表；`order = natural` 时忽略，按路径排序的扫描结果 |
| `resources` | 资料登记（Markdown）。`role` 是自由字符串，已知值 `characters \| timeline \| reference \| data`；图片 / 附件是自动索引的，不写进清单 |
| `exclude` | 导出与检查跳过的前缀；目录以 `/` 结尾。`资料/` 恒被排除 |
| `export` | 项目级导出的默认值（`mode` / `toc` / `chapterBreak`）；单文档导出不受影响 |

约束：

- **只存四件事**：身份、次序、资料、导出默认值。brief、检查规则、AI 记忆、主题都不进来。
- 清单不重复文件树：`spine` 只表达顺序，文件是否存在以扫描结果为准；失效路径跳过并计数提示。
- 目录不展开：`spine` 只收文件路径。`卷一/` 这种写法不解析。
- 未知字段忽略（向前兼容）；缺字段全部有缺省。
- 清单路径一律相对项目根、`/` 分隔。含 `..` 或解析后越出根目录的路径**直接丢弃**，不读取。
  清单能把任意文件送进 AI 上下文，这是真实攻击面，不是洁癖。

### 谁写

- 应用写：新建项目、转为项目、调顺序、登记资料、改标题与导出默认值。
- AI **只读**。清单是机器状态，不参与 diff 审阅；让 agent 改它等于绕过唯一的写回通道。
- 用户手改：读时校验。坏 JSON 不阻塞打开，降级为隐式项目 + 一次性提示。

### 读写

- `PlatformFs` 新增 `readRootFile(root, path)` / `writeRootFile(root, path, text)` / `createRootDir(root, path)`，
  桌面端与浏览器端都实现；写入沿用主进程的「同目录临时文件 + rename」原子替换。
  路径先过 `safeRelativePath()`（拒绝绝对路径与 `..`），桌面端 IPC 再 `assertInside` 一次。
- **不要**为读清单放宽 `scan()` 的 Markdown 过滤：`files` 会流向文件树、搜索、命令面板、AI 上下文。
- 清单随根切换、外部变更读一次并缓存，不要在每次按键或每次 AI 任务时读盘。
- 桌面端监听 `.writara/project.json`（watcher 原来只推 `.md` 变更），改动后重读并刷新树。

## 4. 文件树：从根节点开始

现在的树是「标题条 + 根的孩子们」；改成**根目录本身就是树的第一行**。

```
▾ 📁 长夜                    ← 根节点（项目名 / 文件夹名）
    ▾ 📁 卷一
        📄 01-起.md
    📄 00-前言.md
```

- 行内容：折叠箭头、文件夹图标、`title`（清单 title，缺省文件夹名）。
- **非 Markdown 资源也进文件树**：图片、附件（pdf / docx / xlsx / zip…）与其它文件用不同图标显示，
  点击用系统默认程序打开；它们不参与搜索、命令面板与 AI 文档列表（那些仍只收 `.md`）。
- 资源文件**自动索引**（扫描即索引），不写进清单；清单 `resources` 只登记需要角色语义的资料 Markdown。
- 右侧 `＋`（新建文件）与 `⋯`（项目菜单）从原 `.wr-sidebar-root` 头部移到这里，hover 显示；
  原头部条取消，搜索与收起按钮仍在 tab 条上。
- 折叠根 = 整棵树收起，只留根行；折叠状态与其它文件夹共用同一份 `collapsed`（根用键 `""`）。
- 筛选时强制全部展开（含根），沿用现有规则。
- 当前文档高亮、自动展开祖先目录、右键菜单、拖宽、内联重命名全部不变。
- 空白处右键仍走 `onBlankMenu`；根行右键走项目菜单，不要弹「文件夹」菜单。
- 实现：根节点由 `Sidebar` 合成 `TreeNode { name, path: "", children }`，复用 `TreeNodes`；
  不要复制一套渲染，也不要让 `buildFileTree` 为根特判。`TreeNodes` 里按 `path === ""` 路由菜单。

## 5. 项目级导出

这是引入项目概念最主要的收益：把一章一文件，合成一份完整的书稿。

- 范围：`order = custom` 时按 `spine`；否则按路径排序的正文，减去 `exclude`、`资料/` 与指令文件。
  `order = custom` 但 `spine` 为空时退回自然序，避免导出一片空白。
- **两种交付**（都做）：
  - `single`：合并成一册。逐章渲染成 `<article class="wr-doc">`，外面包一层 `.wr-project-chapter`；
    章间 `break-before: page`（`export.chapterBreak` 可关），页码由一次打印自然连续；
    桌面端直接出 PDF，浏览器没有 PDF 通道时下载合并后的单文件 HTML。
  - `bundle`：每章独立 HTML，另加一个索引页（章节列表）；选一个目录写盘（桌面与 Chromium 都走
    目录选择器 + `writeRootFile`），完成后在文件管理器里定位索引页。
- **图片必须逐章解析**：每章相对路径以该章所在目录为基准，不能按项目根统一解析，否则
  `卷一/图.png` 会全部 404。`renderArticle(source, dark, resolver)` 已支持传入每章专属解析器。
- 目录（`export.toc`）：按章收集 h1/h2，合并时对重复锚点追加 `-2`；章内链接仍指向首次出现（已知限制）。
- 读盘失败一章就中止并点名，不静默缺章。
- 单文件导出（PDF / HTML / PNG / Word / ePub）路径完全不变；项目导出复用 `renderArticle` 与 `buildDocument`。
- 命令 id：`export-project-single` / `export-project-bundle`；入口：文件菜单 + 顶栏导出 + 根节点 `⋯`。

## 6. 多文件 AI（逐文件 diff）

- 入口：文件菜单 / 根节点 `⋯` 的「项目 AI 任务…」。
- 范围：项目正文（与导出同一套顺序），用户在对话框里勾选参与的文件；默认全选。
- 运行：把选中的 `.md` 按相对路径复制进 `<userData>/agent-runs/<runId>/`，agent 在副本里改；
  **绝不直接写项目文件**。返回后按文件比对，只列出真正变化的文件。
- 审阅：左侧文件标签（可勾选），右侧行级 diff；用户可以只写回其中几个文件。
- 写回：当前正文走一次 dispatch（可撤销）；其他文件先读盘校验「仍等于运行前的内容」再写，
  编码按原文件保留。写入后给一次整批撤销（逐个校验仍等于写入后的内容）。
- 预算：单文件 12 万字符、合计 24 万字符；超了明确拒绝，不静默截断。
- 项目规范（`WRITARA.md` / `AGENTS.md` + 全局规则 + 记忆）随任务一起注入。
- 不做向量检索、不做自动召回；资料引用（`@资料/人物.md`）仍是后续切片。

## 7. 设置分层

- 全局（`settings`）：主题、字号、栏宽、图片规则、Pandoc、agent。
- 项目（清单）：导出默认值 + `WRITARA.md`。
- 文档：正文自身。
- brief 目前是本机单份，v1 不动；「项目级 brief + 文档覆盖」列为后续，不塞进清单。

## 8. 入口与命名

- 菜单保留「打开文件夹」；打开带清单的文件夹就是打开项目，**不新增「打开项目」**。
- 新增「新建项目…」：选目录 → 写清单（title = 目录名，kind 由用户选）→ 可选写 `WRITARA.md` 骨架
  → 建 `资料/`。不覆盖已有文件，不要求空目录。
- 根节点 `⋯` 里给「转为项目…」：只写清单，不移动文件。
- 最近文件夹列表仍显示文件夹名（现有 `mergeFolders` 按名字去重），不为读标题而异步读盘。
- 窗口标题仍跟文档名，不改成项目名。

## 9. 容错

- 清单坏、版本高、权限被回收：都能打开文件夹，只是退回隐式项目；提示一次，不重复弹。
- 清单里 `spine` 指向不存在的文件：跳过，导出完成后提示「跳过 N 章」。
- 浏览器端没有绝对路径：`title` 属性省略，其余能力照旧；最近项目靠目录句柄。
- 外部改动清单：重读后刷新根节点标题与导出菜单；正在进行的导出用开始时的那份快照。

## 10. 验收

- 无清单的文件夹：树根显示文件夹名，行为与今天逐项一致。
- 有清单：树根显示 `title`；根折叠/展开、筛选、当前文件高亮、右键菜单都正确。
- 坏清单：仍能打开、能编辑、能保存，只有一条提示。
- 项目导出：章序正确、章间分页、页码连续、目录可跳、图片零缺失（headless PDF 抽查）。
- 清单里写 `../secret.md`：不进上下文、不导出、不报错。
- 打字、滚动、打开 20k 行文档无可感知回归（清单读取不参与编辑路径）。

## 11. 不做

- 多根（项目跨多个目录 / 素材在别的盘）：留待真实需求，不预留半套实现。
- 从子目录打开文件时向上寻找项目根：现在工作区仍是文件所在目录（浏览器拿不到父目录），
  所以打开 `长夜/卷一/01.md` 会按「卷一」这个隐式项目处理。要支持得先解决跨平台的父目录访问。
- 项目模板市场、跨项目引用、双链、标签、结构化人物库与时间线。
- 向量检索、全文索引、自动召回、项目级 AI 记忆自动提取。
- 版本历史、自动备份、git 集成、云同步、多标签页。
- 清单承载设置（主题、字号、检查规则、快捷键）。
- 第二份清单（`project.md` / front matter）：一份 JSON 就够。
